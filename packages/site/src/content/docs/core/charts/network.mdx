## Basic example

## Clusters

A network with no colors of its own is colored by the clusters in it: groups of nodes linked more to each other than to the rest, found with the [Louvain method](https://en.wikipedia.org/wiki/Louvain_method) and weighted by `linkSize`, so here the heaviest collaborations pull hardest. Each cluster is named after its most-connected node ("Fay cluster"). The legend lists the clusters largest first, even though this network has only `nodes` and no `data`, and clicking one zooms to it. At most `clusterConfig.max` clusters are kept (12 by default, so each gets its own palette color): while there are more, the smallest joins the cluster it shares the most link weight with, or the largest cluster when it has no links to another. Each name is also written inside its cluster, where it fits clear of the nodes and their labels, shrinking down to `clusterConfig.labelConfig.fontMin` (10px) before it is left off; the legend still names every cluster.

Clusters apply only while the chart's color is its default. Setting `color`, `colorScale`, `colorOrdinal`, or a `shapeConfig` fill colors the nodes as configured instead, and so does more than one `groupBy` level. A network with fewer than two clusters of two or more nodes (no links, or one cluster holding everything) keeps one color per node, as does a node with no links. Set `cluster` to `false` to turn clustering off. `linkColor: "source"` colors each link like its source node's cluster, and charts linked with `link` share the clusters' colors when they share their names.

<Playground chart="Network" code={clusters} controls={["cluster","linkSize"]} />

`clusterConfig.label` names each cluster: it receives the row of the cluster's most-connected node, the cluster's index (0 is the largest), and every member's row. `clusterConfig.labelConfig` styles the names written on the chart (`fontMax`, `fontMin`, `padding`, and TextBox settings such as `fontColor` or `fontWeight`), or `false` leaves them to the legend.

<Playground chart="Network" code={clusterNames} controls={["clusterConfig"]} />

## Data driven link size

`linkSize` takes an accessor returning each link's `weight`, which d3plus runs through a square-root scale (`linkSizeScale`) to set stroke thickness—heavier links render thicker. The thinnest link is `linkSizeMin` pixels wide (1 by default) and the widest `linkSizeMax`, which defaults to half the smallest node's radius so that even the heaviest links stay narrower than the nodes they join.

<Playground chart="Network" code={dataDrivenLinkSize} controls={["linkSize","linkSizeMin","linkSizeMax"]} />

## Directional arrows

`arrows` draws an arrowhead at the node boundary to show edge direction. Use `"target"`, `"source"`, `"both"`, or a per-link accessor for bi-directional edges. `arrowSize` overrides the automatic size.

<Playground chart="Network" code={directionalArrows} controls={["arrows","arrowSize"]} />

## Size legend

Sizing nodes with `size` adds a size legend. When there's room it is drawn in the open space around the nodes (see `legendInset`), otherwise in the bottom-right corner. It is drawn with the chart's own radius scale, which Network fits to the space between nodes. Zoom in and the circles keep their size while the labels change to the values those circles now represent on screen.

<Playground chart="Network" code={sizeLegend} controls={["size","sizeMin","sizeMax","sizeLegend"]} height={500} />

## Legend inset

A network gathered in the middle of a wide chart leaves its corners empty, so the legend is drawn in one of them, over a translucent box, instead of taking a margin. Zoom in and the nodes slide under the box while the legend stays readable. Set `legendInset` to `false` to keep the legend in its margin.

<Playground chart="Network" code={legendInset} controls={["legendInset","legendInsetConfig"]} height={500} />

## Label placement

A node's label stays inside it when it fits there at a readable size (`pointLabelConfig.fontMin`, 10px by default). Otherwise it moves beside the node, on the side with the most open room, as long as it overlaps no other node or label; a label with no room is hidden, and the node's tooltip still names it. Bigger nodes are labeled first. Set `labelPosition` to `"inside"` to keep every label inside its node, shrinking it to fit, or `"outside"` to put every label beside its node.

<Playground chart="Network" code={labelPlacement} controls={["labelPosition","pointLabelConfig"]} height={500} />

## Link tooltips

Hovering a link highlights it and the two nodes it connects, and its tooltip names them ("alpha → beta") above the link's own fields. Hovering a node lists its number of connections and, when `linkSize` gives the links different values, its strongest links with their values; `nodeTooltipLinks` sets how many (`false` for none). `linkSize`, link `shapeConfig` functions, and tooltip accessors all receive each link with `source` and `target` set to the data of its nodes, so here a link between two nodes in the same `group` draws darker. Click a link to focus and zoom to it and its nodes; click it again, or the background, to reset.

<Playground chart="Network" code={linkTooltips} controls={["nodeTooltipLinks"]} />

## Link color

`linkColor` colors each link. A key or accessor whose values are numbers colors the links on the chart's colorScale, which then shows the links' values beside the legend for the nodes' colors. Strings are used as colors when they parse as one, or else as categories in the chart's palette, the way `color` colors nodes. `"source"` or `"target"` colors each link like one of its nodes. Arrowheads take their link's color. When the chart also sets `colorScale` for its nodes, nodes and links share that one scale. Because links are thin lines, a light theme's ramp starts at a mid-tone rather than a near-white tint, so the lowest values still show (`colorScaleConfig.ordinalRamp`).

<Playground chart="Network" code={linkColor} controls={["linkColor","colorScaleConfig"]} height={500} />

## Link labels

`linkLabel` writes a key or accessor's value at the middle of each link, between the nodes it joins, on a pad of the chart's background so it reads over the line. `linkLabelConfig.rotate` runs the text along each link (`"along"`, the default, kept upright) or keeps it level (`"horizontal"`), and takes font settings such as `fontSize` and `fontColor`. A label that would cover a node, a node's label, or another link's label is hidden, the thickest links' labels kept first.

<Playground chart="Network" code={linkLabels} controls={["linkLabel","linkLabelConfig"]} />

## Self-loops

A link whose `source` and `target` are the same node draws as a loop outside the node, pointing into the widest gap between the node's other links (or away from the middle of the network when it has none). Its thickness comes from `linkSize`, its label from `linkLabel` (at the loop's far point), and `arrows` draws its arrowhead where it comes back into the node. Several loops on one node fan out side by side, the heaviest in the middle. A loop has the same tooltip, hover, click focus, and keyboard focus as any other link, and a node's tooltip lists it as "↻ node".
