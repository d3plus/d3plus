The d3plus engine (`@d3plus/core`) is imperative: you create an instance,
configure it, and render it. Official **wrapper packages** fit that lifecycle
into the major front-end frameworks, so you pass a declarative `config` and the
wrapper handles instantiation, updates, and teardown for you.

| Framework      | Package                                                              | Render with                                                  |
| -------------- | -------------------------------------------------------------------- | ------------------------------------------------------------ |
| React          | [`@d3plus/react`](https://www.npmjs.com/package/@d3plus/react)       | `<Treemap config={…} />`                                     |
| Vue 3          | [`@d3plus/vue`](https://www.npmjs.com/package/@d3plus/vue)           | `<Treemap :config="…" />`                                    |
| Svelte         | [`@d3plus/svelte`](https://www.npmjs.com/package/@d3plus/svelte)     | `<div use:d3plus={{constructor, config}} />`                 |
| Web Components | [`@d3plus/element`](https://www.npmjs.com/package/@d3plus/element)   | `<d3plus-treemap>` (`.config = …`)                           |
| Angular        | [`@d3plus/angular`](https://www.npmjs.com/package/@d3plus/angular)   | `<d3plus-viz [viz]="Treemap" [config]="…" />`                |

Every wrapper is a thin layer over the same shared core (in `@d3plus/dom`), so
their [runtime behavior](#shared-behavior) is identical.

## Install

<Tabs syncKey="flavor">
  <TabItem label="JavaScript">
    ```sh
    npm install @d3plus/core
    ```
  </TabItem>
  <TabItem label="React">
    ```sh
    npm install @d3plus/react
    ```
  </TabItem>
  <TabItem label="Vue">
    ```sh
    npm install @d3plus/vue
    ```
    Requires `vue` (^3.4) as a peer dependency.
  </TabItem>
  <TabItem label="Svelte">
    ```sh
    npm install @d3plus/svelte @d3plus/core
    ```
    Requires `svelte` (4 or 5) as a peer dependency. The package exports a
    single [action](https://svelte.dev/docs/svelte/use): apply it with
    `use:d3plus`, passing the visualization class from `@d3plus/core` and its
    config. Because `config` is reactive, reassigning it (or mutating `$state`)
    drives updates automatically.
  </TabItem>
  <TabItem label="Web Components">
    ```sh
    npm install @d3plus/element
    ```
    Register the elements once (in the browser) with `defineElements()`, then
    use `<d3plus-…>` tags anywhere: plain HTML, Astro, or any framework that
    renders the DOM. Each d3plus class becomes `d3plus-<kebab-case-name>`
    (`BarChart` → `d3plus-bar-chart`). Config is set through the `.config`
    **property** (an object, so it can carry accessor functions, unlike string
    attributes).
  </TabItem>
  <TabItem label="Angular">
    ```sh
    npm install @d3plus/angular @d3plus/core
    ```
    Requires `@angular/core` and `@angular/common` (v20+) as peer dependencies.
    Published in the [Angular Package Format](https://angular.dev/tools/libraries/angular-package-format)
    (partial-Ivy), so it works in your app's AOT production builds.
  </TabItem>
</Tabs>

## Shared defaults

Each wrapper has a way to supply defaults merged ahead of every chart's own
config:

<Tabs syncKey="flavor">
  <TabItem label="JavaScript">
    Merge your defaults into each config yourself, for example with
    `assign` from `@d3plus/dom`:
    ```js
    import {assign} from "@d3plus/dom";

    const defaults = {locale: "es-ES"};
    new Treemap().config(assign({}, defaults, config)).render();
    ```
  </TabItem>
  <TabItem label="React">
    ```jsx
    import {D3plusContext} from "@d3plus/react";

    <D3plusContext.Provider value={{locale: "es-ES"}}>
      <App />
    </D3plusContext.Provider>
    ```
  </TabItem>
  <TabItem label="Vue">
    ```js
    import {provide} from "vue";
    import {D3plusConfigKey} from "@d3plus/vue";

    provide(D3plusConfigKey, {locale: "es-ES"});
    ```
  </TabItem>
  <TabItem label="Svelte">
    ```svelte
    <div use:d3plus={{constructor: Treemap, config, globalConfig: {locale: "es-ES"}}}></div>
    ```
  </TabItem>
  <TabItem label="Web Components">
    ```js
    import {setGlobalConfig} from "@d3plus/element";

    setGlobalConfig({locale: "es-ES"});
    ```
  </TabItem>
  <TabItem label="Angular">
    ```html
    <d3plus-viz [viz]="Treemap" [config]="config" [globalConfig]="{locale: 'es-ES'}" />
    ```
  </TabItem>
</Tabs>

## Shared behavior

Because all wrappers delegate to the same core, they behave identically:

- **Tweening across updates.** The underlying instance is reused when the
  config changes, so the chart animates between states instead of restarting.
- **Structural diffing.** Assigning a config that is structurally identical to
  the current one (including function-valued accessors, compared by source) is
  a no-op: no re-render. Set `forceUpdate` to render on every update
  regardless.
- **Callbacks.** A `callback` runs at the end of each render cycle.
- **Teardown.** The instance is destroyed automatically when the component
  unmounts (or the element disconnects).

| Wrapper        | Config             | Global defaults               | Force re-render         |
| -------------- | ------------------ | ----------------------------- | ----------------------- |
| React          | `config` prop      | `D3plusContext.Provider`      | `forceUpdate` prop      |
| Vue            | `config` prop      | `provide(D3plusConfigKey, …)` | `forceUpdate` prop      |
| Svelte         | action param       | `globalConfig` param          | `forceUpdate` param     |
| Web Components | `.config` property | `setGlobalConfig()`           | `.forceUpdate` property |
| Angular        | `config` input     | `globalConfig` input          | `forceUpdate` input     |
