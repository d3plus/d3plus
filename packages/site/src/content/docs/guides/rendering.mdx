In v4 a visualization compiles to a serializable **scene graph** that is painted
by a pluggable backend. Two backends ship today: **SVG** (the default) and
**Canvas**.

## Choosing a backend

Set the backend with the `renderer` config key:

```jsx
<BarChart config={{data, x: "x", y: "y", renderer: "canvas"}} />
```

```js
new d3plus.BarChart().data(data).x("x").y("y").renderer("canvas").render();
```

| Backend | Best for | Notes |
|---|---|---|
| **`"svg"`** (default) | Most charts; crisp, zoomable, inspectable output; the broadest feature coverage. | Each shape is a DOM node, so very dense charts (tens of thousands of shapes) can get heavy. |
| **`"canvas"`** | Dense, high-shape-count charts where paint performance matters. | Pointer hit-testing is supported via `Path2D`. Output is a raster. |

Both backends consume the same scene graph and support the same configuration,
tooltips, and pointer events — including texture/pattern and gradient fills, which
the Canvas backend paints at parity with SVG — so you can switch between them
without changing any other code.

## Lifecycle and cleanup

A visualization observes its container for resizes and listens for pointer
events. When you remove a chart, call `destroy()` to disconnect the
`ResizeObserver` and remove its listeners:

```js
const chart = new d3plus.BarChart().data(data).render();
// later, when tearing down:
chart.destroy();
```

In **React** this is automatic — the wrapper calls `destroy()` on unmount.

## Responsiveness

A chart sizes itself to its container by default and re-renders on resize. Give
the container an explicit width/height (or let it flow in your layout) and the
visualization fills it:

```jsx
<div style={{width: "100%", height: 400}}>
  <Treemap config={config} />
</div>
```

To pin a fixed size instead, set `width` and `height` in `config`.

### Keeping a chart's shape: `sizeRatio`

A container that only has a width (a column of text, a card in a grid) gives a
chart nothing to take its height from. `sizeRatio` sets the height from the
width instead, as width divided by height, so the chart keeps its shape as it
resizes and the content after it moves with it:

<Playground chart="LinePlot" code={sizeRatio} controls={["sizeRatio"]} height={420} />

`16 / 9` makes a wide chart and `1` a square one. The ratio is used whenever the
chart has no `height` of its own, in place of its container's height: a
container without a height grows to hold the chart. In a container whose height
is set (by CSS, a flex or grid layout, or a `max-height`) and lower than the
ratio asks for, the chart takes the container's height and narrows to keep its
ratio, centered with equal space on both sides, like `object-fit: contain`, so
it never spills out of its box; its loading and no-data messages center over it
too. A chart with an explicit `width` uses that width the same way: its height
is the width divided by the ratio, or, in a shorter box, it narrows and centers
inside the width you set. Either way `width` keeps the full width (the
container's, or yours), and `chart.width()` and `config()` return it, while the
chart draws narrower. An explicit `height` always wins. Not to be confused with a
Plot's [`aspectRatio`](/core/charts/plot/), which keeps one unit of y as long as
one unit of x inside the plot area.

### Breakpoints: `responsive`

`responsive` swaps in other settings when the chart is narrow (or wide). Each
breakpoint gives a `minWidth` and/or `maxWidth` in pixels (both inclusive) and
the `config` the chart takes while its own width, not the window's, is in that
range. Narrow your window, or raise a `maxWidth` in the code, to see these
shorten the title, move the legend below the chart, drop ticks, and finally
hide the legend and the y-axis title:

<Playground chart="BarChart" code={responsiveBreakpoints} panel="code" />

- Every breakpoint in range applies, in list order, so a later one wins where
  two set the same key. Config objects such as `xConfig` or `shapeConfig` merge
  into the chart's own, as they do through `config()`.
- When the width leaves a range, that breakpoint's settings come back off and
  the chart's own return. The chart checks on every render, including the
  redraw a container resize starts.
- Setting a key while a breakpoint holds it (`chart.legend(true)`, or a
  framework wrapper passing new config) changes the chart's own value: the
  breakpoint keeps its value while it is in range, and yours returns after.
- A breakpoint can set `sizeRatio`, for example to draw a square chart on
  phones. It cannot set `data`, `select`, `width`, `height`, or `responsive`.
- With small multiples (`facet`), breakpoints match the whole chart's width,
  not each panel's. A chart `sizeRatio` narrowed to fit a container's height
  matches the full width: the container's, or the `width` you set. Server-side rendering applies the breakpoints the width
  you render at is in.

## Rendering without a browser

The scene graph can also be realized in Node — to an SVG string or a PNG image,
with no browser — via the [`@d3plus/ssr`](https://www.npmjs.com/package/@d3plus/ssr)
package. See the [Server-Side Rendering guide](/guides/server-side-rendering/).
