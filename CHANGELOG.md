# Changelog

All notable changes to D3plus are documented here. This project adheres to [Semantic Versioning](https://semver.org/).

## 4.6.0

### Added

- **Histogram chart.** `new Histogram()` takes raw observation rows and bins the numeric field named by `.value()` (default `"value"`) along a linear x axis, drawing one contiguous bar per bin with x-axis ticks on the bin edges. Bin edges come from `binThresholds` (a bin count, an array of interior edges, or a d3-array threshold generator; default `thresholdSturges`), `binDomain` (`[min, max]`; default the nicely rounded extent of the values), or `binWidth` (uniform bins at multiples of the width; takes precedence over `binThresholds`). `binNormalize` sets what bar heights measure — `"count"` (default), `"density"` (bar areas sum to 1), or `"relative"` (heights sum to 1) — and the y-axis title follows it; the x-axis title defaults to the value field's name. `groupBy` series are binned on shared edges and stacked within each bin, each series keeping the same stack position across bins. Tooltips show the series, bin range, and count (plus the normalized value when not counting); hovering a bar highlights only that bin of that series, hovering a legend entry the whole series. Bars carry no labels by default. Available from `@d3plus/core` and as `Histogram` components in `@d3plus/react`, `@d3plus/vue`, and `@d3plus/element`. (#840; closes #172) [Histogram ↗](https://d3plus.org/?path=/docs/core-charts-histogram--d3plus)
- **Automatic trend lines on Plot charts.** Every Plot-family chart can draw regression lines via `trendLine`: `true`/`"linear"`, `"exponential"`, `"logarithmic"`, `"power"`, or `"polynomial"` (degree via `trendLineConfig.order`). Off by default. Each series gets its own dashed line in its color; `trendLineConfig.group: "all"` fits a single dark-gray line to every point (in a scatter plot where each point is its own id, series come from the parent `groupBy` level). `trendLineConfig.confidence: true` shades a confidence band around linear fits (default 95%; `confidenceLevel`, styled with `confidenceConfig`); any other `trendLineConfig` key (`stroke`, `strokeWidth`, `strokeDasharray`, …) styles the line. Lines and bands draw behind the marks, dim with their series on hover, and grow the axis domain to include them. On a discrete axis the line runs along that axis (vertical and horizontal bars), sampled at each category and fitting non-numeric categories by their order; time axes fit over the dates; stacked charts fit one line to the stack totals. Hovering a trend line (SVG or Canvas) shows a tooltip with the series, fit type, equation, R², and observation count — `trendLineConfig.tooltip: false` turns it off. New `TrendLineConfig` type; `trendLine`/`trendLineConfig` added to `D3plusConfig`. (#846; closes #278)
- **Size legend for sized marks.** Charts that size their marks — Plot bubbles (`size`), Geomap coordinate points (`pointSize`), Network (`size`), and Rings (`size`) — now show a size legend by default: nested circles sharing a bottom edge, drawn with the chart's own radius scale so the largest circle is exactly the chart's largest mark, with a leader line from each circle's top to a label column on the right, under a centered title (the `size` data key, when `size` is a key). It shows the smallest value, the largest, and a round value in between; it appears only when marks are sized by more than one value, and hides itself when it would take more than a third of the chart's width or height. It sits in a new bottom-right corner panel reserved before layout, so the chart body never runs under it: `sizeLegendPosition("right")` (default) takes room from the right margin and shortens a right-side legend or colorScale to end above it; `"bottom"` takes room from the bottom margin and narrows a bottom legend or colorScale to sit beside it. A timeline always stays below the panel. When Geomap points or Network/Rings nodes grow under zoom, the legend keeps its circle sizes and relabels them with the values those sizes now represent, rounded to a clean number. Configure with `sizeLegend` (`true`, `false`, or `(config, scale, {width, height, availableWidth, availableHeight}) => boolean`), `sizeLegendConfig` (`values` — an array or how many to pick — `tickFormat`, `title`, `shapeConfig`, `lineConfig`, `labelConfig`, `titleConfig`, `padding`, `lineLength`, `labelPadding`), and `sizeLegendPosition`. New standalone `SizeLegend` component, usable with any d3 continuous radius scale, plus a `SizeLegend` React wrapper and a `SizeLegendConfig` type. (#842; closes #83) [Size Legend guide ↗](https://d3plus.org/?path=/docs/guides-size-legend--docs) · [SizeLegend component ↗](https://d3plus.org/?path=/docs/core-components-sizelegend--d3plus)
- **Shared multi-series tooltip and crosshair on Plot charts.** Plot charts with a discrete or time axis (LinePlot, AreaPlot, StackedArea, BumpChart, stacked BarChart) now show one tooltip listing every series at the hovered discrete position whenever two or more series have a value there. It triggers anywhere inside the plot area, including the empty space between marks, and snaps to the nearest discrete value. The title is the continuous axis's title (else its data key); a header row names the hovered discrete value (`year | 2011`); then one `name | value` row per series, each led by a small swatch in the series' stroke color (a dot for Lines, a square for Bars and Areas), ordered as the series sit on the chart, top first — so inverted axes like BumpChart ranks still read top-down. StackedArea and stacked bars show raw values, not stacked totals. The tooltip has no arrow: its position is locked to the snapped discrete value on that axis while the other coordinate follows the pointer, and a dashed crosshair — styled with the new `crosshairConfig` (`stroke`, `strokeWidth`, `strokeDasharray`, …), tracking zoom, on both renderers — is drawn through the snapped position, behind Bars and Lines and in front of Areas. Hovered Line points get a marker styled by `lineMarkerConfig` unless `lineMarkers` is already on. While a shared Line/Area tooltip shows, no series is dimmed; hovering a stacked bar highlights its whole stack while the other stacks dim; side-by-side bars never join the shared tooltip. When the shared tooltip doesn't apply (a single series, `tooltipShared(false)`, side-by-side bars) the same snapped, arrowless tooltip and crosshair follow the hovered mark, with its x and y values as rows ahead of any rows the chart already adds. New `tooltipShared` config (default `true`; `false` on BoxWhisker). Tooltip tables now left-align the first column and right-align the others on every chart, and the new `thStyle` config styles header cells. (#841; closes #779)
- **Drill-down morph transitions.** Clicking a parent `groupBy` cell, wedge, or bar on Treemap, Pack, Pie/Donut, and Plot charts to drill into its children now morphs instead of fading. Entering children grow proportionally out of the clicked parent's on-screen rect — or, for Pie/Donut, its angular slice, using real polar interpolation so radius stays constant while arc length grows — with their labels moving into place alongside, while non-clicked siblings shrink toward their own center as they fade. Going back up mirrors it: the reappearing parent animates down from the full size its children occupied (a full circle sweeping into its slice, for Pie) while the former children disappear instantly rather than double-imaging with the content replacing them. (#838; closes #166)
- **`colorDefaults()` overrides the library's default colors.** Every chart, shape, and component gains a `colorDefaults()` getter/setter for `dark`, `light`, `missing`, `on`, `off`, `sequential`, and `scale` (a d3 ordinal scale or a plain array of colors). Overrides merge into the current defaults, work through `.config({colorDefaults: {…}})`, and `RESET` restores the originals, including the chart's own categorical scale. Setting it on a chart reaches everything it draws — legend, tooltip, color scale, timeline, axes, and their nested children: data fills use the override palette, label text picks the override `dark`/`light` for contrast in every chart type (bar labels drawn outside the bar included), and axis/grid lines, the tooltip background, the timeline handle and play button, the Tree link stroke, and the color-scale legend stroke follow the overrides instead of fixed library colors. `colorOrdinal` ramps from the override `sequential`. Each chart keeps its own categorical scale, so assignments don't leak across charts on the same page. New `ColorDefaultsConfig` type; `D3plusConfig` gains `colorDefaults`. (#836; closes #763)
- **Share percentages on Pie, Donut, and stacked bar labels.** Pie/Donut slice labels show the slice's share of the total beneath its name ("Apple" / "26.5%"), matching Treemap's two-line labels and formatted like the tooltip's "Share" row; slices too short for two lines keep a single centered name, and each slice's aria-label includes its share after the value. Stacked bar labels gain the same smaller share line beneath the name, meeting at the bar's center (name-only when the bar is too short; labels you already return as an array are left alone). (#835, #837; closes #443)
- **Stack share on StackedArea and stacked BarChart.** Each stacked Area/Bar datum carries `share`, its fraction of the stack total at its discrete position, so tooltip accessors can read `d.share` the way they do on Pie and Treemap. Shares are measured against the absolute stack total, so negative segments of a diverging stack (a population pyramid) get positive shares and each stack sums to 100%; zero-value filler points for series missing at an x don't affect any real point's share. StackedArea tooltips — and BarChart tooltips while `stacked` is on — show a "Share" row by default, left blank for legend swatches. (#837; closes #783)
- **Warnings for unknown config properties.** Charts, components, and shapes log a console warning when `.config()` (including the React `config` prop) receives a property they don't support, e.g. `BarChart.config() received unknown property "colr".` Typos in nested component configs warn from the component that receives them (`AxisBottom.config() received unknown property "tickFormt".` for an `xConfig` typo). `shapeConfig` keys are checked when set: a top-level key is accepted if any shape type supports it, while a key nested under a shape name must exist on that shape and is reported as `"Bar.strok"`. Each message logs once per page load. New `configWarnings` export from `@d3plus/core` (and `d3plus.configWarnings` in the UMD bundle): `configWarnings(false)` silences warnings for every chart on the page, `configWarnings()` reads the setting. `tooltipConfig` typos only warn once a tooltip is shown; typos inside `titleConfig` and similar TextBox sub-configs aren't reported yet. (#834; closes #764) [Unknown property warnings ↗](https://d3plus.org/?path=/docs/guides-configuration--docs#unknown-property-warnings)
- **Off-screen charts unload, and `detectVisible` uses `IntersectionObserver`.** Charts deferred by `detectVisible` now wait on a single shared `IntersectionObserver` per scroll container instead of each running its own scroll listener and 1s timer, and render once they've stayed in view for `detectVisibleInterval` (1000ms by default; the countdown starts within 25% of a viewport height of the screen, so the charts you land on draw shortly after scrolling stops). Charts scrolled past quickly are never drawn, and leaving view cancels a pending render. New `detectVisibleUnload` (default `true`): a chart that scrolls out of view releases its DOM and scene renderer and redraws without an entrance animation when it returns; the `<svg>` keeps its size so the page doesn't reflow, and data and config are kept so nothing is refetched. A chart that leaves view while its data is still loading is drawn when it returns. While `detectVisible` is on, each chart's own `<svg>` (not the container) gets `content-visibility: auto`, so the browser skips layout and paint of its contents while it's far off-screen; `detectVisible(false)` leaves it unset, which also keeps it out of static SVG/PNG output. `viz.destroy()` releases the observer registration and any pending render. Environments without `IntersectionObserver` (JSDOM, SSR) keep the scroll-polling path and never unload; `scrollContainer` is still honored. (#829, #830)
- **Charts redraw when their web fonts arrive.** `fontExists` no longer treats a family as missing forever: a "missing" result lasts only until a font d3plus has measured finishes loading, the browser is asked to download any declared `@font-face` for a missing family (`document.fonts.load`), and cached text widths are cleared when a measured font loads so wrapping and font sizing use the real font. A chart re-renders once a font it measured text with finishes loading, so titles, labels, axes, and legends switch to the real font and re-measure their spacing without a manual `.render()`; fonts d3plus never measured (icon fonts, the host page's UI fonts) don't trigger a redraw, a font arriving mid-render queues the redraw for after that render, and `destroy()` stops listening. New `onFontsLoaded(callback)` export from `@d3plus/dom` returns a function that removes the callback. Nothing changes where `document.fonts` is unavailable (Node, `@d3plus/ssr`). (#843; closes #742)
- **`@d3plus/math` regression helpers.** `regression(points, type, {order})` returns coefficients, `predict`, R², n, and the x extent, ignoring non-finite and out-of-domain points and returning `null` when a fit isn't possible; `linearConfidence(points, level)` gives the confidence band of a linear fit's mean response; `studentTQuantile(p, df)` and `studentTCdf(t, df)` back them. New `RegressionOptions`, `RegressionResult`, and `RegressionType` types. (#846)
- New translation keys for Histogram ("Count", "Density", "Relative Frequency", "Range", "Value") and trend lines ("Trend Line", "Equation", "Observations", "Linear", "Exponential", "Logarithmic", "Power", "Polynomial"), with `ar-SA`, `es-ES`, `pt-BR`, and `zh-CN` translations. (#840, #846)

### Fixed

- **Legend labels contrast with the chart's background**, the same way axis labels do: dark on a light page, light when the chart sits on a dark background, where they used to render black and become unreadable. A `fontColor` set through `legendConfig.shapeConfig.labelConfig` still overrides the default. (#845)
- **A legend whose swatches don't fit is hidden instead of overflowing.** It previously fell back to one long row of bare swatches that ran off the chart, and a right-hand legend claimed that row's full width (2,000+ px for ~130 entries) as right margin — flipping the plot's x range negative and drawing every mark off-screen. Such a legend now renders nothing and reserves no margin; legends that fit behave exactly as before, including row wrapping and the label-free fallback. The path had been broken since at least 4.0.0 but was masked until #788 stopped merging recycled-color legend entries. (#850)
- **Chart labels honor `fontFamily()` and `shapeConfig.labelConfig`** on Treemap, Pie, Donut, Tree, Rings, Chord, and Priestley. Their cell/node labels always rendered in the default font stack — `.fontFamily("Georgia")` on a Treemap still drew "Helvetica Neue" — and ignored a user's `fontColor`, `fontWeight`, and `fontSize`; per-datum accessors now receive the source data row, as on Plot charts. Network labels honor a user-set `fontColor`. Precedence matches v3: user config overrides chart defaults on Treemap, Pie/Donut, Pack, Priestley, and Network, while Tree, Rings, and Chord keep their layout-computed keys (per-side `textAnchor`, Rings' background-contrast color for outer labels). With no user config, charts keep their own label colors — the Viz's generic fill-contrast `fontColor` default no longer overrides a chart-specific one, so Chord's labels outside the arcs stay black. (#833)
- **Rings `size` actually sizes nodes.** Every sized node previously drew at `sizeMin` and the center node disappeared (its radius came out `NaN`). `sizeScale` is honored (square root by default), `sizeMax` applies even when `sizeMin` is set, every node including the center is sized with one scale whose largest radius is capped so neighbors can't overlap, and a center node too small for its label puts the label underneath the circle in the normal text color instead of drawing a large white label over a small circle. (#842)
- **Charts render gracefully at very small sizes.** A legend squeezed to zero or negative width (BumpChart at 15×200) no longer throws `Cannot read properties of undefined (reading 'map')` from `Legend._rowHeight`; labels that can't fit a single line are dropped and the legend falls back to swatches. Plot-family charts below `xCutoff`/`yCutoff` no longer emit `translate(NaN, …)` on shapes and the legend — hidden axes reserve no horizontal space instead of producing `NaN` padding. (#831; closes #515)
- **BoxWhisker boxes land on numeric discrete categories.** A BoxWhisker whose discrete axis holds numbers (years) with several `groupBy` members per category drew every box at `translate(NaN, …)` because the category value was summed across the group. Numeric categories now land exactly where the equivalent string categories do, in both orientations. (#832)
- **Rings keeps its corner controls after a click re-centers it.** The zoom controls, the top-left back/table-view/search panel, the minimap, and the attribution no longer disappear on re-center. (#839)
- **Minimap viewport box on single-axis Plot zoom.** On a Plot whose zoom rescales only one axis (a BarChart with a discrete x axis, a LinePlot with its default `discrete: "x"`), the box now shrinks only along the zoomed axis and stays flush with the minimap's edge in the other; dragging the box, nudging it with the arrow keys, and clicking the minimap to jump no longer pan along an axis that isn't zoomed. Plots that zoom both axes (`discrete(false)`) and non-Plot charts still shrink the box in both dimensions. (#847)
- **Pie/Donut hover and active stroke emphasis no longer clips** at the chart's edge; the outer radius is buffered for it. (#838)
- Tooltip `tdStyle` now also reaches cells added on the tooltip's first render, not only cells that already existed. `SvgRenderer` and `CanvasRenderer` always dispatch `mouseleave` when the pointer leaves the surface, even if no node was hovered. (#841)
- Legend no longer passes a `lineHeight` setting to its Circle/Rect swatches, which don't have one. (#834)

### Breaking changes

Most of these are changes to defaults: existing charts will look and behave differently with no config change. Visual-regression snapshots will change.

- **A size legend appears by default** on charts whose marks are sized by more than one value (Plot `size`, Geomap `pointSize`, Network/Rings `size`), giving up some right margin for it; charts where it would be oversized (the existing `BubbleChart` story, with `sizeMax: 90` in a 350px canvas) hide it automatically. Set `sizeLegend: false` to opt out. **Rings charts that set `size` now render varied node sizes** where they used to render uniform ones. (#842)
- **Plot tooltips are shared, snapped, and arrowless.** Plot charts with a discrete or time axis show a multi-series tooltip from anywhere in the plot area, with a crosshair; set `tooltipShared: false` for per-mark tooltips (which are also now snapped and arrowless on those charts). **Every chart's tooltip table** now left-aligns the first column and right-aligns the rest — set `"text-align"` in `tdStyle`/`thStyle` to restore a uniform alignment. `tdStyle`'s type widens from `Record<string, string>` to `Record<string, unknown>`. (#841)
- **Pie/Donut slices show a share percentage** beneath their name, and **stacked bars show a share line** beneath their label; StackedArea and stacked BarChart tooltips gain a "Share" row. Override `label` or `tooltipConfig.tbody` to remove them. (#835, #837)
- **Pie/Donut wedges are separated by a 2px background-colored stroke** instead of touching: `shapeConfig.stroke` defaults to the chart's background color with `strokeWidth: 2`. Set `shapeConfig: {strokeWidth: 0}` for the old look; `padAngle`/`padPixel` still apply if you want an angular gap. (#838)
- **Drilling down animates as a morph** on Treemap, Pack, Pie/Donut, and Plot charts rather than a cross-fade. There is no separate switch; `duration: 0` disables it along with every other transition. (#838)
- **`detectVisibleUnload` defaults to `true`.** Off-screen charts release their DOM, and interaction state — zoom, selection, the table-view toggle — is not kept across an unload; `detectVisibleUnload: false` keeps charts (and that state) alive. Deferred charts also now render only after staying in view for `detectVisibleInterval` (1s), so charts scrolled past quickly are never drawn — lower the interval to render landed charts sooner — and each chart's `<svg>` gets `content-visibility: auto` while `detectVisible` is on. (#829, #830)
- **Unknown config properties warn on the console** by default, including through framework wrappers' `config` props. `configWarnings(false)` silences them. (#834)
- **`colorMin`, `colorMid`, and `colorMax` have no hard-coded defaults**; their getters return `undefined` until set, and they resolve at draw time to `colorDefaults`' `off`, `light`, and `sequential`. Default rendering is unchanged. (#836)
- **Legends that can't fit render nothing** and reserve no margin, instead of a row of swatches overflowing the chart. (#850)
- **Legend labels are no longer always black**; they pick a color contrasting with the chart's background. (#845)
- **`fontFamily()` and `shapeConfig.labelConfig` now reach Treemap, Pie, Donut, Tree, Rings, Chord, and Priestley labels.** Charts that set these and relied on the labels ignoring them will change font or color. (#833)

## 4.5.0

### Added

- **Zoom & pan on every chart.** Every chart type now zooms and pans by default, with a control panel (zoom in, zoom out, reset, and a drag-to-zoom brush) pinned to the chart's top-right corner; titles, subtitles, totals, and top/right legends measure the panel off-DOM and wrap or shift to leave room for it. Wheel and touch gestures default to a `"modifier"` scheme that leaves page scrolling alone (Ctrl/⌘ + wheel or a pinch zooms, a plain wheel scrolls the page, one-finger touch pans only once zoomed in); Geomap and Network, being pan/zoom surfaces, zoom on any wheel. The zoom limit adapts to the chart — by default the scale at which the smallest shape fills the chart area — instead of a fixed `zoomMax`. Plot-family charts (BarChart, LinePlot, AreaPlot, StackedArea, BoxWhisker, BumpChart) rescale their linear axes in place instead of scaling the picture, with a new `domainTicks`/`fixedSize` pair on Axis that pins a rescaled axis to its pre-zoom label width so tick-precision changes don't shift the plot area. The brush now draws above the chart's shapes and paints the OS accent color while active. Geomap and Network drop their bespoke zoom wiring for the shared scaffold. Set `zoom: false` to opt out. (#820, #821; closes #85, #161, #780) [Zoom & pan guide ↗](https://d3plus.org/?path=/docs/guides-interactivity--docs#zoom--pan)
- **Restyled, themeable zoom controls.** The zoom buttons are real `<button>` elements with translated `aria-label`s, laid out horizontally in the top-right corner, with inline-SVG icons that render identically across fonts, OSes, and browsers. The built-in style is structural only (sizing, spacing, layout) so a host page's own button chrome applies through the cascade; `zoomControlClassName` adds your own classes (Tailwind, Bootstrap, a design system) and automatically disables the built-in `zoomControlStyle`/`zoomControlStyleActive`/`zoomControlStyleHover` defaults unless you've customized them. `zoomControlIcons` overrides any of the four icons with an HTML string or a mount function `(el) => void | (() => void)` — the escape hatch for a React tree, a Vue app, or anything imperative — run once per button element, not once per redraw. (#817, #822)
- **Minimap / viewport indicator.** Once a chart is zoomed past 1×, a small overview map fades in beneath the zoom controls, sized to the chart's aspect ratio, showing the viewport's position and size plus a live zoom-level label ("2×"). Drag the viewport box to pan, click elsewhere to re-center, double-click to reset, use the arrow keys (Shift for a bigger step) when the box has focus, and Ctrl/⌘ + scroll over the minimap to zoom around the cursor. Works on every chart type, including the Plot family. `.minimap(false)` turns it off; `minimapClassName`, `minimapStyle`, `minimapViewportStyle`, `minimapViewportStyleActive`, and `minimapLabelStyle` restyle it. (#825; closes #81)
- **Search / highlight control.** A search button in the chart's top-left corner expands into a text input. Typing drives `.highlight()` with a case-insensitive substring match against each mark's label (`searchAccessor` to override) that persists as the mouse moves; matches reach across the `groupBy` hierarchy, so searching a leaf also highlights its parent group's legend entry or undrilled cell, and vice versa. Localized match-count feedback ("6 Matches" / "No Matches" / "Match 2/6"), an inline clear button, and Enter / Shift+Enter to jump (pan/zoom) between matches. Opening saves any existing highlight predicate and restores it on close; term, open state, and highlight survive drill-down re-renders. Excluded under SSR. `.search(false)` disables it; `searchControlClassName` restyles the button. (#827; closes #33)
- **Table view.** A top-left toggle swaps the chart for a chart-sized overlay: a scrollable, sticky-header table of the chart's data. Columns sort on click (keyboard-operable, with `aria-sort`); a download button exports the sorted dataset as RFC 4180 CSV with locale-independent raw values (plain numbers, ISO dates) so it round-trips through a spreadsheet; a raw/aggregate toggle appears whenever the chart's `.data()` input and what it actually draws differ in row count. Cells format through the chart's own `.locale()`, default order follows the original `.data()` array, and rows virtualize past 300 so large datasets never land in the DOM all at once. New config: `tableView`, `tableViewClassName`, `tableViewControlClassName`, `tableViewControlStyle`/`tableViewControlStyleActive`/`tableViewControlStyleHover`, `tableViewPageSize` (default 50, or `false`), `tableViewSort`, `tableViewDownload` — all on by default, each individually disableable. (#828)
- **Light/dark basemap theming for Geomap.** The default basemap is now Esri's World Light Gray Canvas, switching to Dark Gray Canvas (with a matching ocean and no-data fill) when the page behind the chart is dark — detected via `prefers-color-scheme`, a `color-scheme` ancestor, or an explicit backdrop, and re-checked on DOM mutation. `tileUrl` and `ocean` accept a `{light, dark}` pair for custom themed basemaps, and the attribution credit follows whichever tileset is active. On the Canvas renderer, tiles and ocean now mount in an underlay `<svg>` beneath the `<canvas>` so the painted geography stays visible through the basemap. ### Fixed

- **Multi-point shapes (`Line`/`Area`) now report a single, consistent datum.** They had no "representative datum," so different accessors disagreed and interactions reported the wrong point. Every paint accessor now sees the same merged aggregate that drives the scene node, id, and aria (#785). Mouse events on `Plot` charts now report the point **nearest the cursor** along the discrete axis — un-zoomed and defined-points-only — instead of the whole-series aggregate, so stacked-area and line tooltips finally name the point under the pointer (#786). This branch also **restores `Line`'s fat invisible hit area** (dropped in the v4 scene rewrite) so hovering anywhere along a line registers — with stroke-aware path hit-testing on the Canvas backend — and fixes two paint regressions it exposed: hovered hit areas rendering solid black, and `LinePlot` confidence bands rendering grey instead of the line's color.
- **Non-plottable (`NaN`/`null`) values are filtered out of `Plot` data.** A `NaN` on an axis previously coerced to `0` (a phantom mark at the baseline) on the aggregated path, or emitted a broken `…L268.75,NaN` coordinate the browser rejects on the raw-leaves `Line` path. `formatPlotData` now drops rows whose `x`/`y` — or a defined `x2`/`y2` — aren't plottable, before domains, stacking, and paint read the data, so a `NaN` measure no longer widens a domain, stacks as `0`, or breaks the path; the point is simply absent. ## 4.0.0

v4 is a ground-up re-architecture of the rendering engine. Charts now compile to a serializable **scene graph** that is painted by a pluggable backend, rather than mutating the DOM directly as they draw. **SVG remains the default backend and the rendered output is intended to match v3** — the public chart API (fluent setters, `config()`, the chart classes) is unchanged. Most users upgrade with no code changes. See [MIGRATION.md](MIGRATION.md) for details.

### Added

- **`@d3plus/render`** — a new package providing the renderer abstraction. It diffs and paints the scene graph and owns the SVG and Canvas backends.
- **Canvas backend.** Every visualization accepts `.renderer("svg" | "canvas")` (default `"svg"`). The Canvas backend paints dense, high-shape-count charts more efficiently and supports pointer hit-testing via `Path2D`. [Example ↗](https://d3plus.org/?path=/docs/core-charts-barchart--d3plus#rendering-to-canvas)
- **`Viz.destroy()`** disconnects the `ResizeObserver` and removes the body `touchstart` listener, preventing leaks when a chart is torn down. The React wrapper calls it automatically on unmount.
- **`@d3plus/types`** — a unified package that re-exports every d3plus type from a single import for typing config objects and parameters. React component types are in a separate `@d3plus/types/react` entry so non-React projects don't pull in React.
- **`@d3plus/core/internal`** — an opt-in entry point exposing the v4 pipeline (layout stages, `ChartDefinition`s, feature modules, `runVizPipeline`, `resolveSpec`, `installFluent`, axis measurement, …) for parity tests and advanced consumers building custom charts. The root `@d3plus/core` entry stays curated to the stable public API; the `internal` surface is not semver-stable.
- Share-of-total percentages in Pie and Donut tooltips. [Example ↗](https://d3plus.org/?path=/docs/core-charts-pie--d3plus#basic-example)
- Sankey link enter/exit animations (stroke-width grows from zero). [Example ↗](https://d3plus.org/?path=/docs/core-charts-sankey--d3plus#basic-example)
- **Motion trails.** Points that move between frames (Timeline play) sweep a tapering "cone" from their previous position to the current one, fading from the mark's color at the head to transparent at the tail. Each cone traces the mark's swept silhouette — a circle capped with a rounded tail, a rect as the convex hull of its corners (corner-to-corner off-axis). On by default for scatter `Circle`/`Rect` marks and Geomap points (opt out with `shapeConfig.Circle.trail: false`); parity across the SVG and Canvas backends. `shapeConfig.Circle.trailPersist` keeps past moves visible too — a number of step-segments, or `true` for a long fading snail-trail. Persistent trails follow the timeline's direction (growing forward, retracting on scrub-back) — a multi-period jump traces through the skipped periods rather than cutting a straight line — and draw as a single shape so overlapping turns don't darken. Setting `trailPersist` automatically switches the chart to a single-period timeline (`brushing: false`) and fixed axes (`axisPersist: true`) — the two conditions a persistent trail needs to stay coherent — so it works with the one option. [Circles ↗](https://d3plus.org/?path=/docs/core-charts-plot--d3plus#motion-trails) · [Squares ↗](https://d3plus.org/?path=/docs/core-charts-plot--d3plus#square-motion-trails) · [Persistent ↗](https://d3plus.org/?path=/docs/core-charts-plot--d3plus#persistent-motion-trails)
- Visual-regression, pipeline-parity, and v3↔v4 chart-compare test harnesses.
- **`colorValidate`** (`@d3plus/color`) — validates a palette against the checks that can be computed from color alone: OKLCH lightness band, chroma floor, colorblind (Machado-2009 protan/deutan/tritan ΔE) separation, and WCAG contrast vs the surface; plus an ordinal-ramp mode. The default categorical palette is now gated against it. [Example ↗](https://d3plus.org/?path=/docs/color-colorvalidate--d3plus#default-palette)
- **`colorRamp`** (`@d3plus/color`) — builds an even single-hue light→dark ramp in OKLab (holds the hue, so the pale end keeps its identity instead of drifting to white). Continuous color scales now step through it. [Example ↗](https://d3plus.org/?path=/docs/color-colorramp--d3plus#basic-example)
- **`highlight(predicate)`** — a standing emphasis: the matching marks keep their color while every other mark is de-emphasized to a neutral gray (highlight one series, gray the rest). Unlike `hover`/`active` it survives pointer movement. [Example ↗](https://d3plus.org/?path=/docs/core-charts-barchart--d3plus#highlighting-a-series)
- **`colorOrdinal(true)`** — treats a discrete color field as *ordered*, coloring it with a single-hue light→dark ramp instead of nominal categorical hues. [Example ↗](https://d3plus.org/?path=/docs/core-charts-barchart--d3plus#ordinal-color)
- OKLab/OKLCH conversions and a WCAG `contrastRatio` helper back the above.
- **Locale-aware `titleCase`.** `titleCase(str, locale)` accepts a locale code (or a `TitleCaseRules` object) and normalizes case in *both* directions — it lowercases ALL-CAPS "shouting" input and minor words, force-uppercases known acronyms (with automatic plurals, e.g. `tvs` → `TVs`), and preserves genuine mixed-case (`McDonald`, `iOS`). Per-language rule sets and a `{style: "sentence"}` mode ship as the new `titleCaseLocale` dictionary (and a `TitleCaseRules` type), exported from `@d3plus/locales`. [Example ↗](https://d3plus.org/?path=/docs/text-titlecase--d3plus)
- **Animated text font-size.** Labels whose font-size changes between renders now ease into the new size, position, and rotation (pivoted on the anchor-aware visual center) instead of snapping — in both the SVG and Canvas backends.
- **Plot circles auto-layer by size.** When a `size` accessor is set, scatter circles paint largest-behind so smaller marks stay visible on top (override with `shapeConfig.Circle.sort`).

### Changed

- **Scene-graph rendering pipeline.** Charts are declarative `ChartDefinition`s fed through a pure draw pipeline (`runVizPipeline`) composed of stages and opt-in **feature modules** (legend, color scale, timeline, zoom controls, title/subtitle/total, back button). Drawing no longer mutates instance state mid-pass.
- **Full, strict TypeScript.** The chart pipeline is now `any`-free; types are generated by `tsc` and shipped with every package.
- Per-chart folder structure (`charts/<Chart>/{index,applyLayout,emit}.ts`), with instance state namespaced under `schema`/`ctx`.
- `@d3plus/data` grouping now builds on `d3-array` (`groups`/`rollups`); the deprecated `d3-collection` dependency has been removed. `nest()` / `nestGroups()` remain exported.
- **Default color palette re-stepped for colorblind safety.** The eight primary categorical slots are new open-color steps chosen to sit inside the OKLCH lightness band, clear the chroma floor, and stay distinct under protanopia and deuteranopia (the slot order — the CVD-safety mechanism — is unchanged). Marks shift hue slightly as a result. [Example ↗](https://d3plus.org/?path=/docs/color-colorvalidate--d3plus#default-palette)
- **Continuous color scales default to a single blue hue** (magnitude reads as one hue getting darker) and diverging scales default to blue↔gray↔red (warm/cool poles that stay distinct under CVD), replacing the previous multi-hue ramp and red↔green diverging. `on`/`off` (green/red) still color boolean data. [Example ↗](https://d3plus.org/?path=/docs/core-components-colorscale--d3plus#linear-scale)
- **`colorContrast` now picks text color by WCAG contrast**, not the YIQ approximation — it returns whichever of the two text tokens has the higher contrast ratio against the background (so e.g. bright greens/teals correctly get dark text). [Example ↗](https://d3plus.org/?path=/docs/color-colorcontrast--d3plus#basic-example)
- **`.sort()` / `shapeConfig.sort` drives paint order.** A sort comparator now stamps a stable per-datum paint depth (`z`) rather than reordering the data array, so mark layering no longer disturbs the data join, layout, or enter/exit animations.
- **Timeline auto-play cadence follows the transition `duration`.** Each period fully animates before the next advances; `playButtonInterval` is the fallback cadence only when `duration` is `0` (v3 advanced on a fixed interval regardless of the transition).

### Fixed

- React charts tween between config/prop changes: the chart instance now persists across updates (`destroy()` runs only on unmount) instead of tearing down and re-entering from scratch on each render.

Playwright/Chromium is now a test dependency, and CI runs a `build:types` declaration-emit typecheck across every package.
- **Docs generation** was rebuilt for the v4 charts: README config tables and Storybook argTypes are derived from each `ChartDefinition`'s fields, the runtime `installFluent` accessors, and the typed config interfaces (not just JSDoc); README source links pin to `main` so regeneration no longer churns every "Defined in" link.
- **Build & packaging.** Every root entry file (`index`, `internal`, `react`, `umd-entry`) is transpiled to ESM; `@d3plus/core`'s UMD/CDN global exposes the v4 pipeline via a `umd-entry.ts` superset while the typed ESM entry stays curated; the release script syncs all workspace versions so none ship pinned to a stale version; `@d3plus/types` ships types-only (no UMD) with `@d3plus/react` as an optional peer so non-React projects don't pull in React.
- **Lint.** `max-lines` (500) and `max-lines-per-function` (100) are now enforced (data dictionaries exempt), which drove several oversized modules to be split.
- **Dev server** live-reload is scoped per tab — editing one chart's dev page reloads only the tabs viewing it, and each tab drops its SSE connection while hidden, so many open dev pages no longer exhaust the browser's per-host connection limit.
- **Contributor docs** (`AGENTS.md`, `CONTRIBUTING.md`) were rewritten for the v4 architecture and the TypeScript / TypeDoc / Storybook toolchain.

### Breaking changes

- **React `forceUpdate` is now a top-level prop**, not a `config` key. Use `<Treemap forceUpdate />` instead of `config={{forceUpdate: true}}`.
- Code that reached into a chart's intermediate DOM/d3-selection internals during the draw pass, or subclassed `Viz` and overrode private `_draw` internals, may need updating — drawing now flows through the scene-graph pipeline. The public fluent/`config()` API is unchanged.

### Known limitations

- The **SVG backend remains the default**; both backends paint shapes, gradients, and texture/pattern fills. The Canvas backend is optimized for dense, high-shape-count charts where paint performance matters.
